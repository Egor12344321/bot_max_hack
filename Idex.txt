## ?? Задача: обработка вебхука MAX

### Что уже есть

- Вебхук зарегистрирован: `https://runiversityadmission.ru/webhook/max`
- Секрет: `runadgtji8284` (в `MAX_WEBHOOK_SECRET`)
- Типы событий: `message_created`, `message_callback`, `bot_started`

### Что нужно сделать

**1. Контроллер для вебхука**

Создать `MaxWebhookController` в пакете `bot/`. Эндпоинт:

```
POST /webhook/max
```

Принимает `@RequestBody` как `Map<String, Object>` (или типизированный `Update` из библиотеки). Возвращает `200 OK` **всегда**, даже при ошибке — иначе MAX будет повторять запрос.

**2. Проверка секрета — через фильтр**

Создать `WebhookSecretFilter` (или `HandlerInterceptor`) в пакете `config/`. Фильтр проверяет заголовок `X-Max-Bot-Api-Secret`:
- Если не совпадает с `MAX_WEBHOOK_SECRET` — вернуть `401 Unauthorized`
- Если совпадает — пропустить запрос дальше

Фильтр применяется **только к `/webhook/**`**, не ко всем эндпоинтам.

**3. Разбор события по `update_type`**

Внутри контроллера — `switch` по полю `update_type`:

```java
switch (updateType) {
    case "bot_started" -> handleBotStarted(update);
    case "message_created" -> handleMessage(update);
    case "message_callback" -> handleCallback(update);
    default -> log.warn("Unknown update type: {}", updateType);
}
```

**4. Как понять, что человек ответил и на что**

Ключевой момент: **бот должен помнить, в каком состоянии находится пользователь**.

**Механизм:**
- В **Redis** хранится сессия пользователя: `session:<user_id>` > `{ state: "WAITING_FOR_LANGUAGE", data: {...} }`
- Когда приходит `message_created` или `message_callback`, ты:
  1. Достаёшь сессию по `user_id` из Redis
  2. Смотришь поле `state` — на каком шаге онбординга пользователь
  3. В зависимости от `state` — обрабатываешь ответ и **переводишь в новое состояние**

**Пример:**
```java
Session session = sessionService.get(userId);

switch (session.getState()) {
    case WAITING_FOR_LANGUAGE -> {
        String lang = extractPayload(update); // "lang_ru"
        session.setLanguage(lang);
        session.setState(WAITING_FOR_CITIZENSHIP);
        sessionService.save(session);
        sendCitizenshipQuestion(userId);
    }
    case WAITING_FOR_CITIZENSHIP -> { ... }
    case WAITING_FOR_EGE_SCORES -> { ... }
}
```

**5. Что такое `message_callback`**

Когда пользователь нажимает кнопку, приходит `message_callback`. Внутри — поле `payload` (то, что ты положил в кнопку, например `"lang_ru"`). Это **готовый ответ** на вопрос бота.

**6. Что такое `message_created`**

Когда пользователь пишет текст. Внутри — `message.body.text`. Это **свободный ввод** (например, баллы ЕГЭ).

### ?? Структура

```
bot/
+-- MaxWebhookController.java    // POST /webhook/max
+-- WebhookSecretFilter.java     // проверка X-Max-Bot-Api-Secret
+-- BotStateService.java         // управление состоянием онбординга
L-- MaxBotService.java           // отправка сообщений и кнопок

session/
+-- Session.java                 // модель сессии
+-- SessionState.java            // enum состояний
L-- SessionService.java          // работа с Redis
```

### ?? Важные правила

- **Всегда возвращать `200 OK`** из вебхука — иначе MAX будет повторять.
- **Логировать каждое событие** с `user_id` и `update_type`.
- **Не логировать** `initData`, токены, персональные данные.
- **Состояние хранить в Redis** с TTL 1 час.
